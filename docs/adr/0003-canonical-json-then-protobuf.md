ADR 0003: Canonical JSON wire format in Phase 1, protobuf in Phase 03
=====================================================================

Status: Accepted (2026-05-02)

Context
-------

The .proto schema is the durable wire-format contract (Phase 0 lock).
Implementation choice for Phase 1 is separate: protobuf-generated code adds
build-time tooling (protoc) and binary opacity that slows iteration on the
trust path.

Decision
--------

Phase 1 implementations (`messages.py`, `secure_bus.py`) serialize as
canonical JSON: `sort_keys=True`, `separators=(",", ":")`, payload bytes
hex-encoded. Field names mirror the .proto schema 1:1.

Phase 03 (ROS2 port, codename Mirage) replaces the JSON encoder with
protoc-generated bytes from the same `.proto` file. Envelope contract
(`Envelope` dataclass, signed-blob composition, verification rules) does not
change.

Consequences
------------

Positive:
- No protoc toolchain required for Phase 1.
- Wire payloads are human-readable in tcpdump and test failures.
- Signatures verify byte-for-byte under the canonical encoding.

Negative:
- Larger payloads on the wire (acceptable in-process; matters at hardware tier).
- Hex-encoding bytes inside JSON is awkward but explicit.
- Two encoders to maintain across the Phase 03 cutover (mitigated by the
  envelope contract being the unit of test).

Mitigation:
- The envelope dataclass and verification logic stay constant across the
  cutover. Only the inner payload encoder changes. Existing trust-engine and
  consensus tests continue to apply.

Amendment (2026-05-15) — Observation field rename
-------------------------------------------------

PRD "Range-only trust voting" (ADR 0015) replaces `Observation.rel_x,
rel_y` with `Observation.range_m, bearing_rad` on the wire. This is a
breaking change to the canonical-JSON envelope contract for
`KIND_OBSERVATION`: signature bytes are not portable across the rename,
and any previously-captured signed `Observation` envelope will fail
deserialization.

We accept the break rather than carrying both shapes:

- Specter-1 has no external signers. The entire consumer set is in this
  repo: `src/specter/demo/orchestration/step.py`, `src/specter/ros2/
  agent_node.py`, `tests/eval/runner.py`, `tests/eval/test_profiling.py`,
  and a small number of unit tests.
- A version-bumped parser branching on `Envelope.version` would carry the
  legacy shape forever for no benefit. The Phase 03 protobuf cutover
  remains the only structural wire-shape change of consequence.
- `proto/messages.proto` is updated alongside the dataclass so the
  Phase 03 cutover lands clean.

Going forward, intentional breaking changes to canonical-JSON-encoded
payloads continue to require an ADR; the ADR notes that "external signer
coordination" is the criterion for choosing additive-with-version over
clean-break.
